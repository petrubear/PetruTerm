# gpui Chrome Migration — M0 (Foundation Spike) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer, with real code and a real dogfood pass, whether gpui can host PetruTerm's terminal grid (via `alacritty_terminal`) and leader-key dispatch reliably enough to justify M1–M5 of the full chrome migration.

**Architecture:** A second binary target (`gpui-petruterm`) inside the existing `petruterm` package, sharing the library crate with the current wgpu/winit binary. It opens a gpui window, spawns a real shell via the existing `term::Terminal`, and paints its grid through a new `TerminalGridElement` (custom `gpui::Element`) using gpui's native text system — no custom glyph atlas. A chorded leader-key binding spawns a second terminal side-by-side to prove input dispatch reaches real business logic.

**Tech Stack:** gpui (git, pinned rev) + `gpui_platform` (git, same rev), `alacritty_terminal` 0.25 (existing), PetruTerm's existing `term::Terminal`/`Pty`/`Config` (unmodified).

**Spec:** `docs/superpowers/specs/2026-08-30-gpui-chrome-migration-design.md`

## Global Constraints

- All work happens in a dedicated git worktree on branch `gpui-migration` (created via `superpowers:using-git-worktrees` at execution time, per the spec's isolation strategy). `master` and the existing `petruterm` binary must not be touched or broken by any task in this plan.
- `gpui` and `gpui_platform` are both git dependencies pinned to the **same** commit `rev` (gpui core is on crates.io but the platform-bootstrap crate is not, and versions must match) — obtain the rev via `git ls-remote https://github.com/zed-industries/zed main` in Task 2, Step 1, and reuse that exact rev everywhere. Commit `Cargo.lock`.
- No custom glyph atlas for the terminal grid — use gpui's native `text_system()`/glyph sprite atlas, per the spec's default (Zed's own terminal element does the same).
- Tests are for business logic only. There are no new business-logic units in M0 (it reuses `term::Terminal`/`Mux` as-is) — GPU rendering, layout, and input are verified by manual dogfood, not automated tests. Do not write a test harness for painting.
- Every step that needs the user to look at a running window is a dogfood step: describe exactly what to run and what to look for, then stop and ask the user to confirm before continuing — GPU windows cannot be captured from the agent sandbox.

### Task 1: Expose PetruTerm's existing modules to a shared library crate; add the `gpui-petruterm` binary target

- [ ] **Step 1: Mint a throwaway `winit::event_loop::EventLoopProxy<()>` for the wakeup parameter**

`Terminal::new` requires a `winit::event_loop::EventLoopProxy<()>` (PetruTerm's wakeup mechanism is currently coupled to winit even though gpui owns the window in this migration — see spec's Repaint Reliability section). For M0, sidestep this without touching `Terminal`'s signature (that refactor belongs to a later milestone, once the real gpui-native wakeup path from Step 4 below is proven): create a `winit::event_loop::EventLoop<()>` purely to call `.create_proxy()` on it, then drop the `EventLoop` object without ever calling `.run()` or opening a winit window. gpui owns the actual window; this proxy exists only to satisfy `Terminal::new`'s type.

```rust
// src/gpui_shell/mod.rs
fn throwaway_wakeup_proxy() -> winit::event_loop::EventLoopProxy<()> {
    let event_loop = winit::event_loop::EventLoop::new().expect("create throwaway EventLoop for wakeup proxy");
    event_loop.create_proxy()
    // `event_loop` drops here without ever running — never opens a winit window.
}
```

```rust
use std::rc::Rc;
use std::sync::Arc;
use petruterm::app::pty_schedule::WakeupGate;
use petruterm::config::Config;
use petruterm::term::Terminal;

pub fn spawn_terminal(cols: u16, rows: u16, cell_w: u16, cell_h: u16) -> anyhow::Result<Rc<Terminal>> {
```

- [ ] **Step 3: Implement `TerminalGridElement`**

Confirm the exact `alacritty_terminal` 0.25 cell-iteration API before writing this — check how `src/app/mux/mod.rs` around line 1193 already consumes `term.renderable_content()` in this same codebase (same `alacritty_terminal` version) as the ground truth for field names, rather than guessing.

```rust
// src/gpui_shell/terminal_element.rs
use std::rc::Rc;
use gpui::{
    App, Bounds, Element, ElementId, GlobalElementId, InspectorElementId, LayoutId, Pixels,
    Point, Window, fill, point, px, size,
};
use petruterm::term::Terminal;

pub struct TerminalGridElement {
    pub terminal: Rc<Terminal>,
    pub cell_width: Pixels,
    pub cell_height: Pixels,
}

impl gpui::IntoElement for TerminalGridElement {
    type Element = Self;
    fn into_element(self) -> Self::Element { self }
}

impl Element for TerminalGridElement {
    type RequestLayoutState = ();
    type PrepaintState = ();

    fn id(&self) -> Option<ElementId> { None }
    fn source_location(&self) -> Option<&'static core::panic::Location<'static>> { None }

    fn request_layout(
        &mut self,
        _id: Option<&GlobalElementId>,
        _inspector_id: Option<&InspectorElementId>,
        window: &mut Window,
        cx: &mut App,
    ) -> (LayoutId, ()) {
        let cols = self.terminal.cols as f32;
        let rows = self.terminal.rows as f32;
        let mut style = gpui::Style::default();
        style.size.width = (self.cell_width * cols).into();
        style.size.height = (self.cell_height * rows).into();
        (window.request_layout(style, [], cx), ())
    }

    fn prepaint(
        &mut self,
        _id: Option<&GlobalElementId>,
        _inspector_id: Option<&InspectorElementId>,
        _bounds: Bounds<Pixels>,
        _request_layout: &mut (),
        _window: &mut Window,
        _cx: &mut App,
    ) {
    }

    fn paint(
        &mut self,
        _id: Option<&GlobalElementId>,
        _inspector_id: Option<&InspectorElementId>,
        bounds: Bounds<Pixels>,
        _request_layout: &mut (),
        _prepaint: &mut (),
        window: &mut Window,
        cx: &mut App,
    ) {
        // Background.
        window.paint_quad(fill(bounds, gpui::rgb(0x1e1f29)));

        self.terminal.with_term(|term| {
            let content = term.renderable_content();
            for cell in content.display_iter {
                if cell.c == ' ' || cell.c == '\0' {
                    continue;
                }
                let origin = point(
                    bounds.origin.x + self.cell_width * (cell.point.column.0 as f32),
                    bounds.origin.y + self.cell_height * (cell.point.line.0 as f32),
                );
                // NOTE: signature below is expected-shape, not source-verified — confirm
                // against `crates/gpui/src/text_system.rs` and
                // `crates/gpui/src/text_system/line.rs` at the pinned rev before relying on
                // this. This is the ligature-bearing path (multi-char shaped runs), NOT
                // single-glyph `paint_glyph` — required to reproduce/rule out the #11127 /
                // #48699 symptom in Task 4.
                let shaped = window.text_system().shape_line(
                    cell.c.to_string().into(),
                    px(14.0),
                    &[gpui::TextRun {
                        len: cell.c.len_utf8(),
                        font: window.text_system().default_font(),
                        color: gpui::rgb(0xf8f8f2).into(),
                        background_color: None,
                        underline: None,
                        strikethrough: None,
                    }],
                );
                let _ = shaped.paint(origin, self.cell_height, window, cx);
            }
        });

        // Cursor.
        let cursor = self.terminal.cursor_info();
        if cursor.visible {
            let cursor_origin = point(
                bounds.origin.x + self.cell_width * (cursor.col as f32),
                bounds.origin.y + self.cell_height * (cursor.row as f32),
            );
            window.paint_quad(fill(
                Bounds { origin: cursor_origin, size: size(self.cell_width, self.cell_height) },
                gpui::rgba(0xf8f8f280),
            ));
        }
    }
}
```

- [ ] **Step 4: Wire keyboard input and mount the root view**

```rust
// src/gpui_shell/mod.rs (continued)
use gpui::{Context, FocusHandle, KeyDownEvent, Render, Focusable, div, prelude::*};
use terminal_element::TerminalGridElement;

pub mod terminal_element;

pub struct GpuiShellRoot {
    pub terminals: Vec<Rc<Terminal>>,
    pub focus_handle: FocusHandle,
}

impl GpuiShellRoot {
    pub fn new(cx: &mut Context<Self>) -> Self {
        let terminal = spawn_terminal(80, 24, 9, 18).expect("spawn initial terminal");
        Self { terminals: vec![terminal], focus_handle: cx.focus_handle() }
    }

    fn on_key_down(&mut self, event: &KeyDownEvent, _window: &mut Window, _cx: &mut Context<Self>) {
        // M0 minimal: forward printable characters only. Full key-event mapping
        // (control chars, KKP, etc.) is out of scope for the spike.
        if let Some(ch) = &event.keystroke.key_char {
            if let Some(terminal) = self.terminals.first() {
                terminal.write_input(ch.as_bytes());
            }
        }
    }
}

impl Focusable for GpuiShellRoot {
    fn focus_handle(&self, _cx: &App) -> FocusHandle { self.focus_handle.clone() }
}

impl Render for GpuiShellRoot {
    fn render(&mut self, window: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        window.focus(&self.focus_handle, cx);
        div()
            .track_focus(&self.focus_handle)
            .on_key_down(cx.listener(Self::on_key_down))
            .flex()
            .size_full()
            .children(self.terminals.iter().map(|t| TerminalGridElement {
                terminal: t.clone(),
                cell_width: px(9.0),
                cell_height: px(18.0),
            }))
    }
}
```
